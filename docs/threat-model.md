# Threat model

## Security objective

Help users understand observable plugin behavior without giving inspected code
an execution path or exposing unrelated user data.

The tool cannot prove that a plugin is safe, recover intent from every binary,
or guarantee detection of all malicious behavior.

## Assets

- User credentials, private files, environment, and personal data.
- Integrity and availability of the desktop session and host system.
- Scanner and report integrity.
- Accuracy and provenance of findings.
- Confidentiality of any data considered for later LLM analysis.

## Adversaries and hostile inputs

Assume a target can deliberately contain:

- malformed manifests and parser edge cases;
- symlinks, hard links, special files, deep trees, huge or sparse files;
- path traversal and confusing Unicode names;
- compressed, generated, minified, encoded, or obfuscated content;
- native binaries for the host architecture;
- terminal escapes, QML/HTML/Markdown injection, and prompt injection;
- source designed to exhaust CPU, memory, storage, or output limits;
- Git metadata intended to mislead provenance checks; and
- code that is already running when an enabled plugin is reviewed.

## Trust boundaries

### Target plugin

Untrusted. The scanner may read bounded regular-file content but never execute,
source, import, or evaluate it.

### Scanner

Trusted code exposed to hostile parsers and filesystem structures. It runs in a
Bubblewrap sandbox with a private network, PID, IPC, UTS, and mount view. Only a
read-only target, minimal runtime, private temporary area, and controlled output
are visible.

### Broker

Trusted and unsandboxed enough to construct containment. It must use canonical
paths, fixed arguments, cleared environment, safe file descriptors, and strict
plugin-ID resolution. Target content must never influence Bubblewrap options or
host paths.

The broker enters a transient systemd user scope before target resolution. It
independently verifies the scope identity plus cgroup-exposed memory, swap,
task, and aggregate CPU limits; process rlimits disable core dumps and cap open
descriptors. The parent requests a 35-second systemd lifetime and Bubblewrap
retains an independent 30-second deadline, but live `RuntimeMaxSec`
verification remains an explicit decision in ADR 0003. The broker fails closed
if the user manager or verified cgroup-v2 controls are unavailable.

### Omarchy wrapper

Trusted but hosted in the same unsandboxed `omarchy-shell` process as enabled
plugins. It must remain small. An already-running malicious plugin may tamper
with the desktop or reviewer presentation; the independent CLI is the recovery
and higher-assurance interface.

### Optional Omarchy audit input

Hostile external evidence selected by an explicit caller, not generated by this
project. The broker pins a non-symlink regular-file descriptor and exposes only
that descriptor read-only inside the scanner sandbox. The scanner accepts only
an explicitly named pinned format, bounded strict JSON, and a plugin ID matching
the parsed target manifest. Upstream paths are labels and are never opened.
Because the current upstream report lacks a target digest, its snapshot remains
an explicit unknown and its observations cannot replace independent evidence.

### Report

Untrusted until schema, type, size, and relationship validation succeeds. Every
production QML `Text` primitive explicitly uses `Text.PlainText`; relying on
Qt's default `Text.AutoText` would allow hostile markup interpretation and even
remote image loading. Plugin-controlled strings also receive control-character
handling and display limits. Single-line metadata flattens layout whitespace so
hostile names, titles, paths, command arguments, kinds, or author descriptions
cannot create apparent headers or rows; bounded explanation, evidence, and
diagnostic blocks retain line breaks only as inert plain text.
The broker canonicalizes the validated typed report before QML performs its
second parse, so duplicate members and non-canonical producer bytes are not
forwarded.

### Dependencies and updates

Dependencies add parser and supply-chain attack surface. Pin direct dependencies,
review transitive changes, retain checksums, generate an SBOM for releases, and
publish signed checksums/provenance where practical. A reviewed plugin report is
bound to its bounded file inventory and root digest, not merely its name or
version claim. Git revision and working-tree state are not currently reported;
target-controlled Git metadata must not be treated as trusted provenance.

### LLM boundary

No LLM or external network exists in version 1. A future stage must not access
the target or home directory directly and must show the user a redacted outbound
payload before disclosure.

## Primary attack classes and controls

| Attack | Initial controls |
|---|---|
| Target code execution | Scanner has no target-execution or subprocess path; no imports or shell evaluation; empty runtime limits exploit utility |
| Arbitrary file read | Empty filesystem view; only target is read-only mounted; symlinks, special files, and multi-link regular files are never opened |
| Host modification | Dedicated output and temporary areas; read-only runtime; no session sockets |
| Network access | Private network namespace with no shared host network |
| Path escape | Descriptor-relative `openat2` selection uses beneath/no-symlink/no-magic-link/no-cross-mount resolution; the already-open target descriptor enters Bubblewrap; scanner child opens enforce the root mount ID |
| Parser and enumeration denial of service | Batched bounded directory reads; indexed rather than per-operation whole-file evidence lookup; file/depth/byte/output limits; verified systemd memory/swap/task/CPU scope; independent wall timeout; core/file-descriptor rlimits |
| Report/diagnostic injection | Strict JSON schema; pre-QML 4 KiB normalized broker diagnostics; explicit `Text.PlainText` on every production text primitive; structural regression guard; control-character normalization |
| False reassurance | Explicit limitations; no safe verdict or opaque score |
| False positives | Parsed context, correlated behavior, benign fixtures, separate confidence |
| Update drift | Bounded file/root digest plus scanner-version and policy-version binding; Git revision/dirty state remains unreported |

## Residual risks

- Scanner or kernel vulnerabilities may escape containment.
- Bubblewrap recursively carries nested mounts into the read-only target view,
  but descriptor-relative child opens reject mount crossings and verify each
  opened descriptor's mount ID. Kernel or mount-ID implementation defects
  remain residual risk.
- The opened plugin tree is not an atomic snapshot. Inode, link-count, size,
  mtime, and ctime comparisons detect observable ordinary-file replacement;
  they cannot prove the tree never changed during the complete scan.
- The target bind is read-only but not proven `noexec`; containment does not
  replace the scanner's invariant that target content is never passed to an
  execution API.
- Static analysis can miss generated, encrypted, environment-dependent, or
  semantically complex behavior.
- Binary inventory cannot establish what a native helper will do at runtime.
- An enabled malicious plugin already has user-session authority before review.
- A compromised build/release channel can replace the reviewer itself.

These risks must remain visible in user-facing reports and release documentation.
